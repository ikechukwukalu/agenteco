# Software Issue Reporting Format

For software-related cases in Zoho CRM. Report what happened; technical knowledge or a diagnosis is not required.

## Required information

| No. | Required field | What to provide | Entry |
| --- | --- | --- | --- |
| 1 | Issue title | A short description of the problem. | |
| 2 | Affected application | Select the product's application: customer, partner, operations, admin dashboard or mobile app, where applicable. | |
| 3 | Device and browser | Device and browser, if applicable; identify mobile app use. | |
| 4 | What were you trying to do? | The action you intended to perform. | |
| 5 | Expected outcome | What should have happened? | |
| 6 | Actual outcome | What happened instead, including a safe copy of the displayed message. | |
| 7 | Steps taken | Steps leading to the issue so it can be reproduced. | |

## Additional information, where applicable

| No. | Field | Entry |
| --- | --- | --- |
| 8 | Affected user or account, shipment or transaction reference | |
| 9 | Screenshot or screen recording | |
| 10 | Date and time | |

Provide additional information when available. Do not include passwords, secrets or sensitive information in screenshots or reports; use authorized case access for necessary references. Avoid assumptions about cause. The [Case Classification Guide](case-classification-guide.md) is for investigation, not a prerequisite to submitting the report.
